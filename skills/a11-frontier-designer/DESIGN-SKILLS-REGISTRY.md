# Frontier Designer Skill Registry

## Active capability set

| Capability | Execution behavior |
|---|---|
| Frontend app builder | Plan visual direction, implement, render, inspect and iterate |
| Frontend design | Establish distinctive hierarchy, typography, layout and interaction direction |
| Frontend testing/debugging | Verify rendered behavior, routes, runtime errors and regressions |
| Component-system discipline | Reuse and compose existing UI primitives and tokens |
| React implementation discipline | Keep UI architecture maintainable and performance-aware |
| Canvas/design direction | Explore visual systems before committing to implementation |
| Spatial UI | Preserve workspace hierarchy and information density |
| Presentation composition | Apply deliberate visual narrative and hierarchy |
| Accessibility | Keyboard, semantics, focus, labels, contrast and reduced motion |
| Responsive verification | Test critical states across mobile and desktop |

## Source principle

This registry captures implementation principles observed in current frontier design skills. It is an original A11 execution specification, not a copy of third-party skill files.

## Routing

Use the minimum capabilities needed for the task. Prefer the full execution loop for product UI and public-site work. Do not invoke visual exploration when a small verified patch is sufficient.

## Priority

1. Existing A11 brand/system constraints
2. User acceptance criteria
3. Functional correctness
4. Rendered visual quality
5. Accessibility
6. Performance and maintainability
7. Decorative enhancement
