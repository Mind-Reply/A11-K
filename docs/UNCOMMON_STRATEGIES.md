# Uncommon Strategies

## 1. Recovery before replacement
When a product fails, recover the strongest existing implementation before rebuilding it. Preserve working routes, content, analytics and integrations.

## 2. Decision compression
Do not optimize for more features. Optimize for fewer steps between signal, decision and verified outcome.

## 3. Shadow competition
Before a production change, let competing specialist proposals target the same measurable outcome. Keep only evidence-backed improvements.

## 4. Failure-budget design
Treat failure modes as product surfaces. Every important route has a known-good state, health contract, fallback and owner gate.

## 5. Portfolio as one organism
Shared observability, deployment contracts, recovery rules and design primitives; distinct public identities and positioning.

## 6. Proof over presentation
A feature is not complete until a real path works and its failure path has been tested.
