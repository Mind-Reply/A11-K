# Portfolio Execution Matrix

## Objective
Turn the existing estate into a small number of exceptional, working products without destroying useful source material.

## Tracks
| Track | Primary outcome | Specialist trio | Safety gate |
|---|---|---|---|
| MindReply | revenue-ready flagship | Architect / Builder / Breaker | production + ownership |
| A11-K | decision/recovery platform | Architect / Builder / Breaker | owner gate for consequential actions |
| ResellerPro | transaction/domain platform | Architect / Builder / Breaker | billing + legal |
| Radar | evidence-to-action intelligence | Architect / Builder / Breaker | provenance |
| WhatsApp Router | reliable communications routing | Architect / Builder / Breaker | provider/compliance |
| AUREL | premium brand/product | Architect / Builder / Breaker | IP/provenance |
| Brushworks | creative commerce | Architect / Builder / Breaker | commerce/legal |
| OpenMontage | distinctive creative product | Architect / Builder / Breaker | rights/provenance |
| Pointer | focused acquisition product | Architect / Builder / Breaker | privacy/analytics |
| Control Plane | private operating console | Architect / Builder / Breaker | owner-only |

## Required sequence
1. Inventory existing code/content before replacement.
2. Create a reversible working branch or backup.
3. Architect proposes one conventional route and one uncommon high-leverage route.
4. Builder implements the smallest complete vertical slice.
5. Breaker attacks functionality, UX, security, performance, provenance and recovery.
6. Decision engine scores evidence: value, reliability, speed, uniqueness, maintainability, risk.
7. Promote only when acceptance checks pass.
8. If recovery confidence is low, LATCH and require owner approval.

## Shared definition of done
- real user journey works end-to-end
- responsive and accessible
- production error/loading/empty states
- secrets remain outside source
- provenance/licensing status known
- telemetry and health checks exist
- rollback/fallback path tested
- canonical URL identified
- no duplicate product created without a merge reason

## Product philosophy
Do not optimize for feature count. Optimize for a memorable interaction, a sharp job-to-be-done, measurable conversion, and a recovery path when reality disagrees with the plan.
